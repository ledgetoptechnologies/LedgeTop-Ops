# Access Groups Read capsule loader

This source-only helper separates the read-only Cloudflare Access Groups credential from Wrangler's existing OAuth credential used by management D1 operations. It does not create API tokens, invoke Cloudflare, or perform D1 work. Its production trust pins are all zero, so the loader refuses before filesystem or subprocess access until an operator provisions and independently reviews a protected capsule and exact pins.

The helper accepts no paths, purpose, token, account, group, fetch function, or command from callers. The fixed PowerShell unsealer reads only `C:\Users\fstor\.codex\private\ops-access-group-read\trust.json` and `access-group-read.dpapi`. It validates exact config shape, SHA-256 pins, purpose, current account/group identifiers, the `Access:Groups Read` account-scope assertion, CurrentUser owner SID, token validity window (maximum 24 hours), protected owner+SYSTEM ACLs, reparse-free paths, ciphertext hash, DPAPI CurrentUser unprotect, and plaintext token hash/shape. It launches only the script whose bytes match the pinned unsealer hash, with a process-local PowerShell `Bypass` execution-policy flag because this machine's default policy blocks unsigned scripts; no system policy is changed and the script's exact hash is checked first. Failures are fixed safe errors; provider details and token bytes are not written to logs or environment variables. The token is returned in memory for the separately pinned Access-group GET adapter only.

Cloudflare currently exposes Access Groups Read as an account-level API permission, not a group-scoped permission. The application must still request only the group UUID and name bound in its separate reviewed group-observation config; the credential itself can read other Access groups in that account. Wrangler 4.118.0's supported OAuth scope list has no Access Groups scope, so this permission cannot be added to its current OAuth login request. See the [Cloudflare API token permissions](https://developers.cloudflare.com/fundamentals/api/reference/permissions/), [Access Groups list endpoint](https://developers.cloudflare.com/api/resources/zero_trust/subresources/access/subresources/groups/methods/list/), and [Wrangler OAuth scope options](https://developers.cloudflare.com/workers/wrangler/commands/general/).

Provisioning is intentionally outside this code. A later trusted operator must create the account-scoped read-only API token, record its short validity window and permission/resource in an exact reviewed trust JSON, encrypt the token using the fixed DPAPI purpose `ltds-ops-access-group-read-capsule-v1` under the same Windows CurrentUser, apply protected ACLs with only that owner and SYSTEM, and separately pin the raw config and unsealer hashes in a trusted local distribution. The account/group IDs and permission statement in the config are pinned assertions from that review; the loader does not infer token permissions from token bytes. SYSTEM can read the protected ciphertext but cannot DPAPI-decrypt a CurrentUser capsule. Do not copy the token into Wrangler files, `CLOUDFLARE_API_TOKEN`, command arguments, receipts, or logs, and never fall back to D1/Wrangler OAuth when the Access Groups GET is denied.

The offline Node tests use a synthetic marker and temporary DPAPI fixture only. They do not use credentials, logins, network calls, or production paths. The live all-zero pin check remains the production default.
