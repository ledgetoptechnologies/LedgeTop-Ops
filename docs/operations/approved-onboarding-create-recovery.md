# Approved onboarding create completion

An approved onboarding batch can contain several PA creates that share one observed authorization generation. Each accepted create advances that application generation. Later immutable creates, including a business contact released after its company ACK, can therefore meet a valid generation conflict.

The native directory drain now completes only exact durable approved onboarding creates through the existing0181 recovery ledger. It replays the original command to establish a transport-validated generation conflict, observes the current inventory generation, appends a same-payload successor, and dispatches that successor before observing the next candidate's generation. The original command, approval and audit remain immutable. Ordinary staff commands and updates do not acquire this delegation. Existing onboarding-admin, native-drain and create-recovery gates still apply; no new configuration or migration is required.

The service derives the original reviewer from the approved decision or approved shared-company child receipt. This is durable delegation, not a fabricated human session. Original admission/profile, current edit/link/enrollment grants and denies, selected enrollment/source/application/history/origin, active local records and current parent relationship/version remain required. Interactive recovery retains its real session-expiry checks. Linked clients use the same ACK-backed parent transport as normal dispatch. Create transport rechecks authority after the capability request immediately before POST.

A typed normal generation conflict can recover within the same bounded drain. Historical terminal conflicts must establish fresh typed proof before a successor is allowed. Each dispatched successor consumes the existing command budget and uses the same drain deadline; no inner retry loop, original outbox rewrite, changed payload or relaxed PA CAS is used. An accepted request with a lost response is retried under its original idempotent command, not replaced with a new client.

The migrated219 local D1 regression covers a same-generation multi-client/company batch, linked parent identity, immutable successor shape, wrong-code conflicts, revoked reviewer, native deny, changed source epoch, capability-await revocation, a real enrolled parent update during recovery, uncertain transport, lost accepted response, and non-onboarding exclusion. These are local synthetic transport tests; live staging acceptance and production readiness require the normal reviewed rollout.
