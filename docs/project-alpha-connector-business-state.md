# Observe, suspend and resume a deployment-owned connection

Authenticated administrators with global, deny-aware `integrations.manage` can GET or POST `/api/admin/integrations/project-alpha/connectors/{sourceId}/state`. POST uses the ordinary same-origin CSRF protection and accepts only `{expectedVersion, state}`, where state is `suspended` or `active`. Source identity, credentials, labels, visibility, registration and retirement cannot be supplied through this route. A nonempty valid deployment manifest and an already registered selected source are required; a manifest-disabled source cannot be resumed.

Resumption verifies the current registered producer identity and active revision against the declared manifest before any coordination write. The server passes that matched deployment context through the existing coordinator and final split-credential validation; callers cannot select credentials. Existing internal callers retain their original behavior. Missing credentials or a later race can leave a durable coordination hold, which must be observed and explicitly recovered rather than bypassed.

GET and the successful POST return the safe current connector summary plus coordination availability and any unfinished operation's public recovery version/action. They do not reconcile or materialize deployment configuration. After a stale or uncertain response, observe with GET; use the existing guarded `recover-portal-update` operation when coordination is unfinished. Never replay an uncertain state mutation automatically. Recovery cancels the unfinished coordination attempt; it does not replay an activation.

These routes use the existing coordinated state algorithm. They are **not a universal maintenance switch**. A deployment-managed source without portal enrollment may subsequently be reconciled to its manifest state by an ordinary projection request. The status route reports the current transition; it does not promise that an unenrolled source stays suspended.

For a reviewed two-source cutover, independently verify that the manifest includes both exact identities and the secondary is already portal-enrolled. Suspend that secondary first, then the primary. Deployment reconciliation prevalidates every source before writes and rejects the enrolled secondary's intentional manifest mismatch, preventing it from restoring the primary. Events ingress reads the suspended registry without reconciling. Observe both versions/states and unfinished coordination, and drain previously admitted work separately: suspension invalidates old transaction proofs, but is not proof that every already running request completed.

Resume the primary, then the secondary using freshly observed expected versions. Business resumption deliberately leaves a previously suspended secondary portal purpose suspended. Portal access requires its existing separate explicit configure/activate workflow. Existing source, credential, signing and authority checks remain mandatory; the state route does not create enrollment, grants or permissions and requires no migration or new feature flag.
