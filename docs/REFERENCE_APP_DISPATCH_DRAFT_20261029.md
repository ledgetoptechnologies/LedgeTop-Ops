# Reference application dispatch draft — disabled

The production worker calls `processReferenceOne`, which unconditionally returns false. No configuration or public request can activate this lane; database admission remains hard-disabled. The synthetic-only factory exercises the shared draft dispatch core against the actual v45 journal and `ReferenceProvider`, with explicitly injected test custody/transfer/result stand-ins. The factory is not an authenticated custody issuer or production runtime.

The draft calls the real provider submit and status interfaces, binds returned job identity and opaque pipeline digest to the existing journal, and delegates reservation transfer or result handling to explicitly provided interfaces. A succeeded upstream job is not marked published. Failure or lease expiry holds the journal instead of automatically reclaiming potentially live I/O.

NO-GO: The draft selects existing journal entries only in synthetic tests; it does not enqueue jobs, bind an attested runtime provider to the stored provider identity, implement a durable transfer-grant reservation/uncertain-ACK recovery, issue source custody, establish a real writer fence, integrate the real result bridge, schedule polling without a busy loop, publish a model, or provide operator recovery for held leases. The synthetic tests do not establish durable receipt, live HTTP service behavior, restart across real processes, v45 migration compatibility with an installed DB, or NodeODM execution. Enablement requires those implementations and verified drain of old writers. Do not wire the synthetic factory to runtime configuration or release this branch.
