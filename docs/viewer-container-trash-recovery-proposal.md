# Container trash recovery (draft)

The opt-in `LTDS_CONTAINER_RECOVERY_REGRESSION=1` HTTP test demonstrates that a project trash retry can return success after a dataset moved but its membership insert failed. The current retry excludes already-trashed datasets from its discovery, so the dataset remains a separate trash item. This is a synthetic interruption, not a production-data test.

Create a durable container plan in the same database transaction as the parent archive and trash record, before child effects. Snapshot exact child entity IDs and types, ownership basis, and stable child trash/mutation identities. Preexisting independent trash must remain distinct unless explicitly included by a defined contract. A task's dataset belongs in the plan only when ownership is established; shared datasets must not be moved by another task's plan. Preserve the existing CSV retention check before any destructive transition.

Process planned children idempotently. Bind each resulting child trash record to its planned identity transactionally when metadata trash is created or when a managed storage mutation completes. After a crash, resume from the plan rather than scanning arbitrary historic trash; a completed child without membership can then be associated from its recorded identity. Hold restore, purge and automatic purge of the container and its planned children while the plan is incomplete. Revalidate ownership and lifecycle state, and preserve a clear retryable or inspectable status for conflicts. Old incomplete trash operations without a plan are ambiguous: do not attach unrelated items by timestamps or guess ownership.

Required checks include interruption after parent planning, child intent, filesystem move, database completion, and before membership; repeated recovery; separate workers; shared datasets; unrelated preexisting trash; competing containers; restore and purge during an incomplete plan; and CSV retention with legacy or mixed-version writers. Activation also requires a rollout fence against old processes that bypass the plan. No release or data migration is authorized by this proposal alone.
