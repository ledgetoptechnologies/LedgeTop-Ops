# Directory finalization nonmutation snapshot contract

`scripts/staging-directory-nonmutation-snapshot-verifier.mjs` verifies already-supplied JSON captures. It never invokes Wrangler, reads credentials, queries D1, or prints rows. Its result contains only the database/revision attestation, per-table row counts and SHA-256 hashes, and changed table names.

The capture must contain exactly every table and column in `CLIENT_DIRECTORY_NONMUTATION_MANIFEST`. Rows must contain every declared column as a JSON scalar. Tables are sorted by the declared SQLite primary key using type-tagged UTF-8 bytes before every complete row is hashed in migration column order. Missing tables or columns, unknown schema, duplicate/null keys, unsafe numbers, oversized input, and excessive row counts fail closed.

Capture provenance must attest `environment: "staging"`, `database: "Client"`, the exact staging Client database ID `b6f653ab-9acd-4421-9ad0-207754b59aeb`, and a full 40-hex deployed source revision. These are strict capture-contract labels, not independently authenticated facts: this offline verifier cannot establish where a supplied file originated. Prefer `{ "mode": "primary-bookmark", "bookmark": "<opaque capture bookmark>" }` when the capture mechanism supplies a bookmark. A D1 bookmark provides sequential consistency; it does not make separate reads snapshot-isolated or atomic. If no bookmark is available, use `{ "mode": "primary-read-unbookmarked", "bookmark": null }`. Both modes report `atomicityClaim: "not-attested"`; only separate, real transactional-capture evidence could justify a stronger claim. The verifier does not transform separate paginated queries into an atomic snapshot.

This bounded manifest covers native Viewer grants, portal folder bindings, public projects/file index/share records, service-home workspace/principal grant heads and their audit/receipts, workspace publication commands/heads/snapshots/history/receipts, and native recipient/delivery commands/heads/history/receipts. Full `shares` rows are included, including volatile `access_count` and `last_accessed_at`; do not run public-share probes between captures, and expect any background share access to make comparison fail. The manifest excludes other volatile telemetry (share events, sessions, generic audit logs, health/reconciliation state, and content-start events). It also excludes legacy verified-recipient delivery authority and unrelated portal identity/membership/directory tables. Equality means only `declared-capture-equality-only`: the declared rows supplied in the two files hash equally. It is neither proof of capture origin nor proof that the live or whole database was unchanged.

The capture producer must use explicit `SELECT <manifest columns> FROM <manifest table> ORDER BY <manifest primary key>` queries against the intended staging Client database, preserve JSON scalar types, enforce its own pagination bounds, and retain the raw captures privately. Do not place tokens, URLs, bookmarks, principal values, or row data in logs or acceptance reports. Run the verifier locally with Node tests via:

```text
node --test scripts/staging-directory-nonmutation-snapshot-verifier.test.mjs
```
