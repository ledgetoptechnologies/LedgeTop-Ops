# Viewer–Processing real coordinator pilot (draft)

Status: preparation only. Do not start the coordinator, engine, network, drains or pilot until the Processing and Viewer owners have reviewed the exact fixture, resources and restoration plan. No production Viewer or TrueNAS operations are part of this test.

Its identity record includes the run owner, project, dataset, task, attempt, provider, provider task, photo count and manifest digest. Non-prepare phases deliberately fail closed. The network-none container was limited to 0.5 CPU and 1 GiB, and the mismatched converter was masked. Task-owned container and fixture files were removed; the retained archive remains. This is not a run of the real helper, a coordinator test, a derivative-render test, or exact-release-image qualification.

Independent review found the existing helper is not ready for a real pilot: it accepts arbitrary roots and endpoints, has no byte/inode cap or meaningful storage reserve, and has a 300-second job lease without heartbeat while allowing one-hour network transfers. Its photo checks are path-based and do not pin a file through hashing and copying. Finish does not recheck all provider and task identities. The JPEG-only helper does not exercise GCP CSV or marks. These are pre-run blockers; revise and test the helper, then independently review its exact new hash before arranging any resources or drains.

Two new unwired guard experiments reject obvious path/owner mistakes and bound and hash-check 40 photo copies using no-follow file descriptors. Independent review found they still rely on a trusted supervisor: configurable boundary arguments are not authority, path checks do not pin directories or prove read-only mounts, and the database is not yet bound to an immutable fixture identity. Preflight all input bytes and available space/inodes before copying; account for output/extraction, timeout and safe incomplete-fixture cleanup. Test mount aliases, directory swaps, database replacement and input mutation. Neither guard establishes isolation or authorizes a pilot.

The photo-copy experiment now opens the input and destination directories and all 40 source files before checking total size and storage reserve, then copies through descriptor-anchored paths and verifies and synchronizes copied bytes. A bounded staging test passed, including preflight rejection without a partial copy. This does not prove source mount read-only, detect every bind-mount alias, reserve space against competing writers, account for engine output, or handle interrupted partial-copy cleanup; the guard remains unwired.

An additional synthetic staging test changed a source file during copying and the guard rejected the fixture. The partial copy remained for inspection; the test cleaned only its own synthetic fixture. This does not establish immunity to every concurrent mutation or provide production cleanup.

The unwired boundary experiment can now seal a private database's device and inode and detects ordinary replacement and extra hard links. Review identified that inode reuse, same-UID replacement, a swap between checking and SQLite opening, and unverified WAL/shared-memory paths remain possible. A trusted supervisor must protect and pin the namespace and bind a random database-internal identity to a protected external identity; a single pathname check is not a fence or pilot authorization.

An additional unwired experiment records a random identity in the fixture database and its private seal; its focused test rejects an internal mismatch as well as ordinary replacement. The two writes are not atomic and an interruption must hold the fixture for inspection. This does not prevent same-UID tampering or the pathname/open race and does not validate WAL/shared-memory identity.

An unwired lease helper checks that the lease is still live before renewing it, aborts on lost renewal or deadline and clears timers when work returns. Two focused tests passed using a fake repository, and a separate in-memory SQLite test verified an expired claim was neither renewed nor allowed to start. Abort is cooperative; it does not stop unresponsive work or descendants, and the helper has not been tested with the full Viewer database or provider. The external supervisor must still enforce deadlines and prevent a second executor from acting while an old one can continue.

After review, the experiment also checks elapsed monotonic time when work returns, so a blocked event loop cannot report success after the deadline; a focused test passed. This does not interrupt blocking work. Fresh per-claim generation, final ownership validation, wall-clock rollback handling, provider abort behavior and a process-level watchdog remain open.

The existing Viewer `claimJob` increments `attempt_count` when a job is claimed. The unwired heartbeat experiment now binds its renewal to the observed count as well as the job, attempt, type and owner; an in-memory SQLite test rejects a different count. This does not fence provider effects, survive database rollback as an external epoch, prove globally unique owners, or establish that the claim count is checked by the normal worker's completion paths.

The lease wrapper now requires a synchronous completion verifier and rejects a false or asynchronous result. An unwired completion experiment checks job, attempt, provider and task identities, claim count, expected next state and a caller-supplied archive hash/size; five focused tests passed on a simplified SQLite schema with synthetic provenance. Review found these observations do not prove which claimant completed a job or independently validate the coordinator receipt and retained archive bytes. Reads need a consistent snapshot, actual Viewer schema/worker tests and identity binding for the dataset, manifest, provider and exact next work. A queued derivative is not a rendered model. The callback and experiment are not a fence or pilot authorization.

Follow-up staging checks passed using the actual Viewer repository/schema: `processSubmit` with a synthetic photo and mock provider, and `processIngest` with the retained PR66 archive and independently supplied expected hash/size. Both satisfy the experimental completion check. The checks were separate attempts, not a same-attempt live-coordinator run; they do not establish fenced claimant ownership, snapshot consistency, a trusted live receipt, derivative execution or rendering.

The completion experiment now wraps its reads in a dedicated SQLite read transaction and rejects nested use. Focused SQLite tests and both actual Viewer worker fixtures passed again. This supplies a consistent database snapshot, not exclusive ownership, independent archive custody or proof that the same claimant completed upstream effects.

A synthetic staging test opened SQLite through `/proc/self/fd/<directory>/viewer.sqlite` after renaming the pinned directory and replacing its old pathname. The test observed and updated the original database, leaving the replacement unchanged. This is evidence for that tested ordering and local filesystem only. SQLite may resolve paths internally; database-file or WAL/shared-memory swaps, mount changes and cross-process behavior remain untested. The actual pilot helper does not use this experiment.

For the opposite ordering, with the directory replaced after SQLite opened the database, a WAL-mode write failed with `attempt to write a readonly database`; neither synthetic database gained the attempted row. This test does not establish safety for other timing, SQLite/VFS versions or mounts. Treat a changed fixture directory as a failure requiring inspection, not as a supported transparent relocation.
