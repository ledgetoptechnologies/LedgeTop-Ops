# Windows signing test fixture

This manually dispatched workflow is a proposed one-time diagnostic, not a release or update feed. It creates a harmless DLL from the inline marker, retains its unsigned copy, signs exactly one copy using the existing `windows-release` environment and its scoped GitHub OIDC identity, and uploads the two files and a hash receipt as a private, one-day GitHub Actions artifact. The DLL must never be executed, shipped, or distributed as an installer. The workflow does not publish a release or modify an update feed.

The job is guarded to the `main` ref, this repository, and `workflow_dispatch`; no pull-request or branch Actions are needed. Actions are pinned to commits and dependency caches are disabled. Before dispatch, review and merge the workflow by PR under the repository policy, confirm the effective branch restriction and signer-role scope remain correct, verify billing and current limits, and verify the pinned action code and its dependencies. Only then may an authorized operator dispatch it on `main`. One signing operation and GitHub Actions usage may be charged. The `windows-release` environment currently has a branch policy; this document does not claim a required human reviewer or that branch restrictions are enforceable on every GitHub plan.

Download the short-lived artifact to an isolated test area, check its hashes against the receipt and GitHub's artifact integrity information, and independently verify the real signer, Microsoft trust chain, profile-specific EKU, and cryptographic timestamp on the same signature. The workflow's Windows signature status and timestamp-certificate presence are diagnostics, not proof that a particular timestamp or signing identity is valid. Treat the output as untrusted until these checks pass. Recreating a certificate profile can change its profile EKU; do not configure a production pin from this workflow alone. This fixture cannot by itself qualify an installer, in-app update, update feed, or deployment.

Local source checks: `node --test scripts/windows-signing-fixture-workflow.test.mjs scripts/workflow-trigger-policy.test.mjs`. These are static policy checks, not a run of the workflow, OIDC, signing, or Windows verification. No Azure roles or GitHub environment settings are created or modified by this workflow.
