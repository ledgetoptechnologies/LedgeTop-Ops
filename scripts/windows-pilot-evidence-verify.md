# Pilot evidence byte check

`windows-pilot-evidence-verify.ps1` compares a caller-supplied manifest against an unqualified local payload. It requires exact commit, version, source archive, receipt, inventory and application SHA-256 pins. It recreates the selected Git archive as a bounded read-only stream and checks every payload file against the inventory. A mismatch, unsupported path or malformed input refuses the check. The Git archive subprocess is limited to 30 seconds and 128 MiB; if stopping the timed-out owned process fails or its exit remains uncertain, the verifier reports its PID and waits for that exact process instead of leaving it orphaned.

The manifest has these exact keys: `schemaVersion` (integer 1), `sourceCommit`, `version`, `sourceArchiveSha256`, `inventorySha256`, `applicationSha256`, `receiptSha256`, and `evidence` (an array). Each optional evidence entry has exactly `classification` (`synthetic`, `installed`, or `connected-live`), `path` (relative to the build root), and `sha256`. Classifications are supplied labels: the script verifies only referenced bytes and never interprets their meaning, authenticates their author, or decides whether an event occurred. It does not inspect credentials.

Pins need an independent trusted source to convey any provenance. Even matching pins and a matching Git archive do not prove the payload was built from that archive, that tests passed, or that installation, connected sync, security review or staging qualification succeeded. The result explicitly leaves all of those claims unverified. The script never changes a receipt, installer gate or release status.
