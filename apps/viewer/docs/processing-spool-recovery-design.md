# Processing archive spool recovery: safety requirements

Status: design only. The current worker does not automatically discover or remove abandoned spools. A crash can leave a partial `.processing-archive-` directory, and a reclaimed job can complete while an earlier worker is still alive and writing. Lease expiration, file age, a PID, a directory name, or an incomplete archive alone is not sufficient authority to delete it.

Any implementation must establish and test all of the following before enabling cleanup:

- Persist a unique spool identity and exact job, attempt, and lease generation before accepting download bytes. Reconcile crashes between reservation, directory creation, and journal updates without treating unregistered files as disposable.
- Hold an exclusive writer lock for the entire spool lifetime, including extraction and promotion. A separate cleaner must acquire a compatible exclusive lock that proves the writer cannot still mutate the spool, even when a database lease has expired or the worker is paused. The lock must work across every supported worker process, container, host, and actual storage filesystem; if that cannot be proven, cleanup fails closed. A process-local mutex is insufficient.
- Under the lock, verify the current journal record and lease generation, constrain traversal to the exact managed parent and unique spool identity, and use descriptor-relative operations with no symlink following. Check that the filesystem objects and identities have not been replaced before and during removal. Never follow provider-controlled names or touch dataset sources, promoted outputs, unrelated jobs, or legacy unjournaled spools.
- Atomically fence new writers and record cleanup intent before removal; make interruptions and retries idempotent. Preserve journal and diagnostic evidence of partial failures, and bound the number and disk/IO cost of cleanup attempts. Only remove files proven to belong to that spool, and stop on any discrepancy.
- Define when a spool is safely disposable from durable processing state and retention policy. Age may control eligibility for a review or retry, but cannot independently establish ownership, writer death, or deletion authority. Failure to determine eligibility leaves data untouched and raises an actionable storage warning.

Qualification must include a worker killed after writing bytes, a paused live worker whose lease is reclaimed, concurrent cleaner attempts, process and host restarts, symlink and object-replacement races, interrupted deletion, journal/filesystem mismatch, legacy spools, and a real deployment filesystem lock test. Tests must demonstrate that active writers and uncertain data remain untouched, that only the exact authorized orphan is reclaimed, and that raw datasets and accepted outputs survive unchanged. No production cleanup or TrueNAS change is authorized by this design.
