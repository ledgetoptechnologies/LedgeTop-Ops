# Static source spool service: disabled skeleton

The candidate Compose file has only explicitly profiled design services, requires disposable host paths and an explicitly supplied image, and must not be applied to TrueNAS. Its mock API and worker mount services exit immediately. The copy entrypoint uses `flock -n -F` followed by Node, but the worker validates only static configuration and then exits 78: it has no network, database, copy or receipt functionality. No route or real source path is enabled.

The future service must not mount Viewer SQLite or the Docker socket. The API-owned transactional request/outbox, bounded authenticated manifest and destination, actor and scope checks, replay-resistant worker authentication, receipt and acceptance idempotency, verified bytes and durable restart state are not designed or implemented here. A file path or a self-signed manifest is not authority. The lock path in this sketch lies in a writable spool and can be replaced unless independently protected; the actual image's `flock` availability and FD behavior are unverified. Multiple replicas, supervisor failure, host restart, ZFS locking, source and spool aliases, ACLs and physical capacity still require qualification. The child read-only overlay must be tested on the actual TrueNAS App configuration with the parent writable; local Docker behavior does not prove absence of alternate writable aliases. Beau controls the host App and filesystem settings. No deployment or NAS change is included.
