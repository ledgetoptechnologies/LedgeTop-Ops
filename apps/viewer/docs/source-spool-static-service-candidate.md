# Static source spool service: disabled skeleton

The candidate Compose file has only explicitly profiled design services, requires disposable host paths and an explicitly supplied image, and must not be applied to TrueNAS. Its mock API and worker mount services exit immediately. The copy entrypoint uses `flock -n -F` followed by Node, but the worker validates only static configuration and then exits 78: it has no network, database, copy or receipt functionality. No route or real source path is enabled.

The future service must not mount Viewer SQLite or the Docker socket. `sourceCopyHandoffContractCandidate.js` models a closed claim and receipt only. All hashes use SHA-256 over compact UTF-8 JSON, with no whitespace, the claim's file-array order preserved, and JSON escaping matching JavaScript `JSON.stringify`:

- `manifestSha256`: array entries have fields in order `relativePath`, `byteSize`, `sha256`.
- `sourceInventorySha256`: array entries have fields in order `id`, `relativePath`, `byteSize`, `sha256`.
- `sealSha256`: the existing `sealed.json` v1 object has fields in order `version`, `attemptId`, `manifestSha256`, `objects`; each object entry has fields in order `id`, `byteSize`, `sha256`. It remains distinct from the source inventory digest.

Every file must have a positive integer size; zero-byte source files are rejected. Receipt equality is a shape check, not stored idempotency or proof that bytes were actually copied. Unicode escaping and ordering interoperability need cross-language qualification before this becomes a wire contract. The API-owned transactional request/outbox, capacity linkage, authenticated transport, actor and scope checks, replay-resistant worker authentication, receipt persistence, verified bytes and durable restart state remain unimplemented. A file path or a self-signed manifest is not authority. The lock path in this sketch lies in a writable spool and can be replaced unless independently protected; the actual image's `flock` availability and FD behavior are unverified. Multiple replicas, supervisor failure, host restart, ZFS locking, source and spool aliases, ACLs and physical capacity still require qualification. The child read-only overlay must be tested on the actual TrueNAS App configuration with the parent writable; local Docker behavior does not prove absence of alternate writable aliases. Beau controls the host App and filesystem settings. No deployment or NAS change is included.
