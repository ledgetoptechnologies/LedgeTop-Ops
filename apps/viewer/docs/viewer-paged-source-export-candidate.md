# Held Viewer source export candidate

`server/viewerPagedSourceExport.js` is an inactive, unmounted experiment. It reads the current finalized dataset, active task/attempt, stored attempt input inventory, and validated GCP snapshot/correspondences within one SQLite read transaction. It produces bounded canonical source and selected-frame byte streams compatible with the Processing `ltds-viewer-source-frames-v1` and `ltds-viewer-selected-frames-v1` candidate formats.

The generated ODM GCP selector is fixed to `text/plain` by the Viewer producer policy. When an immutable GCP snapshot exists, its exact stored UTF-8 `evidence_json` bytes are emitted on a separate `ltds-viewer-gcp-evidence-chunks-v1` NDJSON stream, not mixed into source-file counts. Data pages use canonical unpadded base64url chunks and a mandatory completion trailer; each page has a domain-separated hash over canonical JSON bytes excluding LF, while the stream byte budget includes one LF per page. Signed pins cover ordered page hashes and byte lengths, decoded evidence byte count, and SHA-256 of the exact evidence bytes. This is distinct from `correspondenceSha256` and the generated ODM `gcp_list.txt` digest. The exact stored `content_text` bytes for the generated `gcp_list.txt` are also captured in the same read transaction, checked against the snapshot SHA-256/byte size and semantically revalidated through `getAttemptGcpEvidence()`, then emitted on their own `ltds-viewer-generated-gcp-file-chunks-v1` stream bound to the evidence digest. This makes the actual ODM selector bytes available separately from the evidence record; it does not authorize transfer. The producer validates fatal UTF-8 and bounds evidence to 16 MiB, each canonical page to 65,535 bytes, chunks to 46,080 decoded bytes, no more than 512 pages, and a 24 MiB LF-inclusive budget per GCP stream. The explicit maximum across source frames, selected frames, evidence frames, and generated-file frames is 72 MiB. Dataset file IDs are used as Processing closure object IDs; generated GCP uses `gcp_<attemptId>`, with a collision check. Raw GCP file IDs, paths, and hashes are checked against the immutable GCP correspondence snapshot. `correspondenceSha256` is SHA-256 of UTF-8 `JSON.stringify(evidence.correspondences)` bytes in stored row order. The selected order is copied from Viewer `inputInventory()` exactly: photos first, then other selected inputs, with generated `gcp_list.txt` replacing an older file of that basename.

The function does not accept or infer an authenticated principal, environment, authority, revocation epoch, transfer grant, or source-byte custody. Its result always says `held_authenticated_source_unavailable`, includes `enabled:false`, and has null authority/principal/epoch. It is not imported by an API route or worker. It is test-only framing evidence; it does not create access or authorize a Processing transfer. The source and selected framing plus separate GCP evidence data/trailer schema are draft cross-repository contracts. Processing decoder pairing and independent contract review remain pending; no API route or worker consumes these bytes.

Unsupported file classifications, zero-byte files, stale provenance, incomplete GCP evidence, invalid/current-attempt relationships, frame overflow, excessive preflight metadata (32 MiB), GCP evidence over 16 MiB, GCP content over 16 MiB, and nested transactions fail closed. SQL count/byte preflight runs before repository helpers materialize rows or parse GCP evidence. The producer uses a read-only `BEGIN` transaction and refuses to enter an already-open caller transaction, preventing it from committing or rolling back state owned by another operation. Raw frame size is measured including the JSON array brackets and excluding only the LF delimiter.
