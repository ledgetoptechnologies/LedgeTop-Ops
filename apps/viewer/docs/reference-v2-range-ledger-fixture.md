# Closed v2 reservation and budget fixture

This test-only v2 proposal closes reservation and grant fields around environment, job, immutable manifest, generation, reservation, grant ID and a versioned policy with chunk, request and byte budgets. It does not change v1 or define final wire fields, token transport, signatures, expiry, replay, object inventory or policy negotiation. Production schema numbers are intentionally unallocated until #406, #408 and #409 migration identity and deployed state are reconciled.

The disposable SQLite ledger groups charges by environment, job and manifest rather than grant or generation. It records a charge before a range is served, rejects overlapping repeats and changed budgets, and retains uncertain state on close/reopen. A fake HMAC proof binds actual test bytes, identity, object and range before marking verified. The key and authority are injected test doubles: this is not an authenticated broker status endpoint, receipt issuer, persistent worker offset, snapshot, physical sender fence, multi-host coordination, process-kill test or restore/rollback proof. It deliberately does not establish source authenticity or an atomic grant outbox. Real offset advancement requires independently authenticated broker evidence and verified retained bytes; uncertainty holds.

These tests do not authorize or enable a handler or grant. Production needs trusted issuer/receiver identities, per-object manifest membership and size binding, immutable source custody and purge fencing, exact grant/ACK replay, non-resettable charge accounting, concurrency and crash/restore handling, and a jointly reviewed wire and migration plan. Existing 3× v1 validation remains unchanged.
